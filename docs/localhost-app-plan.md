# План: HyperHDR Day Cycle как локальное веб-приложение

## Цель и исходная точка

Сохранить простой редактор расписания в браузере и запускать его по постоянному
локальному адресу, как веб-интерфейс HyperHDR. Само расписание выполняет фоновый
процесс: закрытие вкладки не останавливает суточное управление подсветкой.

Разработку начать от `master` (`f2a935c`). Desktop-эксперимент с WebView2 и папкой
`v1` не переносить. Солнечные привязки из `feature/location` также не входят в эту
базу; восход и закат можно добавить отдельной задачей после готовности основного
локального приложения. Этот документ описывает будущую реализацию, а не уже
работающие возможности.

## Архитектура

```text
Браузер: редактор, графики и состояние
                  │
        локальные HTTP API и SSE
                  │
Один фоновый процесс приложения
  ├─ раздача HTML/CSS/JS
  ├─ настройки и состояние контроллера
  ├─ суточное расписание и ускоренный предпросмотр
  └─ JSON-RPC-клиент → HyperHDR → подсветка
```

Предлагаемая реализация — Node.js LTS, стандартные модули HTTP, файловой системы и
тестирования, без Express, сборщика, frontend-фреймворка и npm-зависимостей для
первой версии. Общий JavaScript-модуль расчёта расписания используется и графиком,
и контроллером. Это позволяет не поддерживать две независимые реализации
интерполяции в JavaScript и PowerShell.

Зафиксировать поддерживаемую LTS-версию при начале реализации. В пользовательский
архив включить официальный Windows x64 runtime Node.js с лицензиями. Установка
Node.js и пакетов вручную пользователю не нужна. Собственного скомпилированного
EXE, генерации EXE с расписанием, WebView2 и нативного окна редактора не будет;
внутри комплекта всё равно присутствует исполняемый файл runtime `node.exe`.

Адрес по умолчанию — `http://localhost:8787/`; прямой адрес IPv4 —
`http://127.0.0.1:8787/`. Слушать только loopback, согласовать IPv4 и IPv6 для
`localhost` и проверить оба адреса. Не использовать `0.0.0.0` или доступ из LAN.
Порт приложения не связан с портом HyperHDR, который по умолчанию равен 8099.

## Пользовательское поведение

- Запуск приложения поднимает фоновый процесс; ярлык «Открыть редактор» открывает
  локальную страницу в обычном браузере. Повторный запуск не создаёт второй контроллер.
- Основной экран: адрес HyperHDR, проверка подключения, графики яркости и цвета,
  «Применить и запустить», «Остановить», состояние соединения и контроллера.
- Редактирование автоматически сохраняет черновик. Работающее расписание меняется
  только после «Применить и запустить». Показывать, есть ли неприменённые изменения.
- Первое открытие страницы выполняет только проверку `serverinfo`, без включения света.
- Закрытие браузера и переход к инструкции не влияют на суточный режим.
- «Остановить» освобождает управление подсветкой, но оставляет веб-интерфейс доступным.
- Изменение адреса HyperHDR останавливает оба режима; новый запуск требует применения.
- Экспорт EXE и опция трея отсутствуют. Инструкции по использованию, запуску и
  автозагрузке находятся в дополнительном разделе, без desktop-диалогов.
- Тема следует системе по умолчанию; ручной выбор сохраняется отдельно от расписания.

Не добавлять пресеты, импорт/экспорт настроек или выбор каталогов.

## Режимы контроллера

Сервер — единственный владелец управления подсветкой. Браузер больше не отправляет
команды цвета напрямую HyperHDR. Вкладки отображают общее серверное состояние.

Состояния: `stopped`, `waiting`, `daily`, `preview`, `stopping`, `error`.
Все переходы сериализованы. Старый режим прекращает отправку команд до запуска
нового; запоздалый ответ не может восстановить отменённый режим.

**Суточный режим:** вычислять текущие RGB и яркость по местному времени компьютера.
На каждом обновлении брать реальное время заново; после сна, изменения часов или
перехода даты сразу рассчитывать актуальный цвет, не воспроизводя пропущенные шаги.

**Ускоренный предпросмотр:** повторять сутки за 24 секунды с выбранной минуты.
Сервер рассчитывает время цикла по монотонным часам. Запуск останавливает суточный
режим; после завершения предпросмотра суточный режим сам не возобновляется.
Предпросмотр принадлежит конкретной вкладке, с heartbeat и коротким сроком владения
(начальное значение: heartbeat раз в секунду, истечение через 3 секунды).
Пауза, скрытие вкладки, выбор времени и переход к инструкции отправляют остановку.
Если вкладка закрылась или исчезла связь, сервер останавливает предпросмотр по
истечении срока владения; доставка события закрытия не считается гарантированной.
Другая вкладка может явно остановить режим, но не продлевает чужой heartbeat.

Сохранить существующую математику: линейную яркость, RGB smoothstep, переход через
полночь, диапазоны RGB 0–255 и яркости 0–100, уникальные минуты, 2–100 точек каждого
типа. Например, между 100% в 00:00 и 50% в 01:00 в 00:30 должно быть 75%.

## Связь с HyperHDR

На сервере использовать HTTP(S) JSON-RPC по проверенному адресу `/json-rpc`.
Браузер обращается только к API нашего приложения на том же origin; прямой
cross-origin HTTP fetch к HyperHDR не нужен, настройки защиты браузера не меняются.

- Адрес без логина/пароля, query и fragment; разрешены только корень и `/json-rpc`.
- Перед цветом дождаться успешного `serverinfo` с объектом `info`. Таймаут проверки
  3 секунды, повтор через 2 секунды; неверный сервис и отказ авторизации не означают готовность.
- После ошибки цветовой команды суточный режим возвращается к ожиданию готовности;
  предпросмотр останавливается с понятной ошибкой.
- Приоритет 50; одна цветовая команда в полёте. Не накапливать очередь старых цветов.
- Суточное обновление ориентировочно раз в секунду; предпросмотр ограничить,
  например, четырьмя командами в секунду, с пропуском устаревших промежуточных значений.
- Продлевать конечную аренду цвета даже при неизменном RGB: начальный срок 4000 мс
  для суточного режима и 1500 мс для предпросмотра. Проверить запас к частоте обновления.
- Отправлять `clear` только для своего приобретённого приоритета. При неоднозначной
  ошибке доставки и принудительном завершении полагаться на конечный срок команды.
- Ограничить все запросы таймаутами, отключить автоматические HTTP-редиректы.

Предупредить пользователя, что другие контроллеры приоритета 50 нужно остановить.
Захват приоритета между разными программами этой реализацией не решается.

## Настройки и локальный API

Хранить данные в `%LOCALAPPDATA%/HyperHDR-Auto`, отдельно от каталога программы.
Формат с версией, строгая серверная валидация, атомарное сохранение, резервная
предыдущая версия. Ошибка записи должна быть видна пользователю; повреждённый
файл нельзя молча заменить пустым расписанием.

Разделить сохранённый черновик и применённый снимок. Сохранять признак разрешённого
суточного режима: «Применить и запустить» включает его, «Остановить», смена адреса
и запуск предпросмотра выключают. После перезапуска восстанавливать только ранее
явно включённый суточный режим и именно его применённый снимок. На чистом профиле
самостоятельного запуска подсветки нет.

Предлагаемые маршруты:

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/settings` | Черновик, применённая ревизия и предпочтения |
| `PUT /api/settings` | Сохранение валидного черновика с проверкой ревизии |
| `GET /api/status` | Состояние режима, связи и последней ошибки |
| `POST /api/connection/check` | Проверка `serverinfo`, без команды цвета |
| `POST /api/controller/apply` | Применение указанной ревизии и запуск суточного режима |
| `POST /api/controller/stop` | Остановка активного режима |
| `POST /api/preview/start` | Запуск предпросмотра, возврат идентификатора владения |
| `POST /api/preview/heartbeat` | Продление владения предпросмотром |
| `POST /api/preview/stop` | Остановка своего предпросмотра |
| `GET /api/events` | SSE: изменения статуса и ревизий, с переподключением |

При конфликте редактирования из двух вкладок возвращать конфликт ревизии, а не
молча перезаписывать более новые настройки. Ограничить размер JSON и статических
ответов, закрывать SSE-подписки после отключения клиента.

Для локального API проверять `Host`, `Origin` и тип JSON-запроса, использовать
непредсказуемый токен процесса в отдельном заголовке для изменяющих запросов.
Не включать CORS для сторонних сайтов; не принимать изменения через GET.
Раздавать только разрешённые файлы `app/`, блокировать выход из каталога и symlink.
Не публиковать настройки, логи, runtime или исходники сервера как статику.
Не предоставлять API произвольных команд, путей, скриптов или HTTP-проксирования.

Старый `file://` localStorage недоступен новому origin автоматически. Предусмотреть
явную одноразовую миграцию через прежнюю страницу с подтверждением и серверной
валидацией; для первого запуска допустим ручной перенос точек с честной инструкцией.
Миграция не должна запускать подсветку и не должна превращаться в файловый импорт.

## Этапы реализации

1. **Общий модуль расписания.** Вынести в `shared/` валидацию и интерполяцию из
   `app/app.js`, покрыть контрольные точки, полночь и границы. График и сервер
   используют одну реализацию. Пока сохранять работоспособность исходного редактора.
2. **Локальный процесс и настройки.** Добавить `server/`: HTTP-статику, loopback,
   API настроек, версии/ревизии, обработку ошибок записи и защиту запросов.
   Занятый порт проверять рукопожатием: открыть уже запущенный экземпляр своего
   приложения либо показать конфликт с чужой программой; чужие процессы не завершать.
3. **Суточный контроллер.** Добавить RPC-клиент, readiness, состояние, сериализацию
   команд, конечные аренды, применение снимка и корректную остановку. Контроллер
   живёт в том же процессе, дочерние PowerShell-контроллеры не запускать.
4. **Подключение редактора.** Перевести хранение и команды на локальный API,
   добавить SSE, «Применить и запустить», «Остановить» и компактный статус.
   Убрать из интерфейса генерацию EXE, диалог трея и устаревшие инструкции.
5. **Ускоренный режим.** Перенести управление предпросмотром на сервер, добавить
   heartbeat, отмену, переключение режимов и обработку нескольких вкладок.
6. **Запуск в Windows.** Добавить сценарии запуска/открытия/остановки и отдельную
   установку/удаление задачи планировщика для текущего пользователя при входе в Windows.
   Указать постоянный абсолютный путь, запуск без видимого терминала, без прав
   администратора и без повторных экземпляров. Остановка процесса должна учитывать
   штатное освобождение приоритета; принудительная остановка защищена сроком аренды.
7. **Поставка и документация.** Собрать переносимый ZIP с runtime, приложением,
   сценариями и ярлыком. Проверить путь с пробелами и кириллицей, чистый компьютер
   без Node.js, обновление с сохранением настроек и удаление автозапуска.
   Обновить корневой README, `app/README.md` и AGENTS.md под новую архитектуру.

Каталоги: `app/` — интерфейс, `shared/` — общая логика, `server/` — сервер и контроллер,
`scripts/` — запуск и поставка, `tests/` — проверки, `docs/` — решения и инструкции.
Нового дерева `v1/` не создавать. Старые экспортные исходники удалять отдельным
шагом после замены зависящих от них проверок; вручную бинарный шаблон не менять.

## Проверка и критерии готовности

Автоматические проверки без реальной подсветки:

- Равенство расчётов графика и контроллера; контрольные минуты, 23:59/00:00,
  RGB и яркость на границах, ошибочные/повторные точки.
- Работа только на loopback, занятый порт, повторный запуск, запрет обхода каталогов,
  неверные `Host`/`Origin`/токен, ограничения тела и конфликты ревизий.
- Мок HyperHDR: поздний запуск, неверный сервис, отказ авторизации, ошибочный JSON,
  таймаут, перезапуск, backpressure и продление аренды неизменного цвета.
- Остановка во время readiness и цветового запроса, запоздалые ответы, отсутствие
  `clear` до приобретения приоритета, отсутствие команд от старого режима.
- Применение снимка, неприменённый черновик, смена адреса, разрешённое восстановление
  после перезапуска, отключённый режим после «Остановить», повреждённые настройки.
- Предпросмотр: выбранная минута, период 24 секунды, потеря heartbeat, скрытая/закрытая
  вкладка, конкуренция вкладок, переходы preview ↔ daily, ограничение частоты команд.
- Время: переход через полночь, перевод часов, сон/возобновление без очереди старых цветов.

Ручная проверка в браузере: русский интерфейс, компактность, клавиатура, графики,
темы, восстановление связи с сервером, несколько вкладок и работа без интернета.
Windows: запуск после входа, выключение автозагрузки, повторное открытие редактора,
штатное/принудительное завершение и перенос папки с понятной ошибкой пути.
Проверки с реальной подсветкой проводить только по отдельному разрешению пользователя.

Первая версия готова, когда пользователь запускает приложение, открывает localhost,
применяет расписание, закрывает браузер, а контроллер продолжает работать; после
повторного открытия страницы виден актуальный статус, остановка освобождает
управление и не закрывает веб-интерфейс. Пользователю не требуется генерировать
контроллер EXE, устанавливать Node.js или оставлять вкладку открытой.

## Пределы первой версии

Только Windows x64 и текущий пользователь. Без LAN-доступа, Windows Service,
собственного трея, удалённой учётной записи, автообновлений, установщика,
солнечных правил и расширений расписания. Эти возможности не должны задерживать
проверку основного сценария. Desktop-эксперимент не используется как источник кода.
